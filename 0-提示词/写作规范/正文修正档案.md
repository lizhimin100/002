# 正文修正档案

## 标点符号规范

- **引号**：统一使用中文全角弯引号 `””`（U+201C / U+201D），不使用半角直引号 `””`（U+0022）
- **段落**：每行只有一个句号。含两个以上句子的段落拆成单句段
- **句内逗号**：段落内属于同一语流的句子，中间句号改逗号，保持一气呵成的阅读节奏。仅段末保留句号。对话后接叙述动作时，对话末尾用逗号而非句号（如 `”活该发不了财，”菲特一边走……`）
- **省略号**：使用 `……`（两个全角省略号字符，U+2026×2），不用 `...`
- **破折号**：使用 `——`（两个全角破折号，U+2014×2），不用 `--`。每章破折号总数不超过3个（含对话和叙述），声效词后不用破折号（如 `咔咔咔！` 不写 `咔咔咔——！`），段落首尾不用破折号开头或结尾

## 风格要求

### 段落节奏
- 短段落、快节奏，大量单句成段
- 场景之间用直接切换，不写过渡段
- 全章 `……` 分界线不超过两条（仅用于必要的POV切换）

### 叙事
- 白描为主，少用形容词，不堆砌环境氛围描写
- 动作描写连贯、干脆、有节奏感
- 心理活动通过行为和简短内心独白体现，不写长段心理分析
- 幽默感来自主角的行为和吐槽，不刻意搞笑
- 有时间压力和资源数字约束，但不写成流水账

### 系统/面板
- 没有"系统"（不写 `【叮！】`、`【材料已确认】`、`【造物法则运转中】` 等交互式系统提示）
- 面板以静态属性卡形式内嵌：`[字段名]值`，使用半角方括号
- 面板数值随剧情实时更新（如 `[创造下一阶层所需源质]20`）
- 击杀反馈用面板数值变化+叙事描述，不用"击杀弹窗"

### 对话
- 对话简短、口语化
- 不写长篇演讲
- 对话与动作穿插，不单独成块

## 结构参照（样本：异世界，开局变成一座地下城）

### 第一章
- 远景定位 → 核心描写 → 揭示智慧 → 人物出场
- 面板内嵌，不做"他拉出面板"的引入
- 世界常识简介（5-8段单句）
- 主角现状：时间积累、资源数量、倒计时压力
- 行动：开辟第二层 → 地形改造（迷宫+陷阱）→ 创造魔物 → 部署
- 章尾：倒计时归零、地下城现世

### 第二章
- 冒险者涌入（群体，非固定小队）
- 观察、失望、有人组织联合分兵
- 主角观察、"迷宫只能拖延"、赌在魔物上
- 跟随一个冒险者深入通道
- 冒险者发现魔物（伪装植物）→ 试探 → 触发 → 死亡
- 主角获得资源 → 发现"冒险者=资源" → "可持续发展战略"
- 掉落装备/钱币 → 发现钱币宝石加持核心、装备无效
- 章尾："希望剩下那几个家伙的收获不要让我失望"

### 第三章
- 散兵在迷宫中各自遇险 → 陆续死亡
- 主角主动调整魔物位置收割
- 领主部队入场（成建制，不分散）
- 地形锁死发现（本章首发）：尝试改变地形 → 失败 → 二层成功 → 推导规则
- 主角提前感知队伍靠近，主动下令魔物伪装/装死（不等人看到再藏）
- 聪明角色（雷格）靠魔法道具存活力反杀一只魔物
- 主角损失魔物 + 对方知道底细 → 撤退保存
- 时间推进 → 领主控场 → 第一层被摸透
- 章尾：开辟第三层 + `[创造下一阶层所需源质]40`

### 第四章
- 承接前章：魔物避战收割剩余散兵
- 第三层开辟 → 核心转移 → 改造第二层（更大的迷宫）
- 检查第三层 → 发现资源（矿脉）
- 分析：资源吸引人 = 养料来源
- 以新资源为材料创造新魔物类型
- 魔物属性卡（技能精简，3-4个足够）
- 批量造炮灰魔物
- "守卫+宝箱"经典骗局部署
- 章尾：坐等客人上门

### 第五章
- 时间推进 → 领主控场 → 第一层地图被标记
- 聪明角色进入第二层："又是迷宫"
- 遭遇炮灰魔物 → 击杀 → 获得资源碎片 → 推测有矿脉
- 探查至宽广空间 → 多只炮灰守护宝箱 → "宝箱！"
- 制定计划，准备动手（不贸然冲）
- 另一边：领主小队被迷宫折磨 → 分兵（散开=给魔物机会）
- 主角视角：看戏，猎物靠近宝箱怪
- 章尾：宝箱怪等待/某人即将触发

## 魔物创造叙事规范（参照样本）

### 核心原则
- **创造过程通过动作和画面呈现，不通过步骤说明**。不写"第一步/第二步/第三步"，不写"核心机制：……"式的设计文档。
- **灵感可来自前世或入侵者**。新魔物的触发点应该是主角本身灵感或他听到/看到冒险者的行为或抱怨，一句话点醒主角。
- **材料选取一笔带过**。不解释"为什么用这个材料"，读者从面板技能反推即可。

### 叙事节奏（样本验证过的固定模式）

1. **触发**（1-2句）：冒险者的一句话/一个行为 → 主角眼睛一亮
2. **取材**（1句）：从环境中快速提取材料，不解释原因
3. **核心发光 + 命令**（1-2句）：核心亮起 → "魔物，创造！"
4. **变形描写**（2-4句）：材料在空中扭曲、融合、定型——纯视觉，不解释机制
5. **面板**（静态内嵌）：[名称][等级][技能][描述]，无"创造成功！"等系统提示
6. **魔物性格**（1-2句）：诞生后的小动作——羞怯、邀功、蹭核心和主角本体身体——让它"活"起来
7. **命名 + 部署**（1-2句）：随口取名 → 传送到指定位置
8. **部署策略**（可选，另起段）：真真假假混在一起的原则

### 反面示例（禁止）

- `第一步，取材。` `第二步，构思。` `第三步，注入机制。`（教程口吻）
- `核心机制：咒印叠加。喝下第一口，叠加一层咒印。效果：轻微的冰凉感……`（设计文档式说明）
- `这是最关键的一步。`（作者视角点评）
- `五步造怪法`（任何带数字步骤的命名）

### 正面示例（样本 Ch7 水源怪）

```
"好渴啊，没想到这个地下城里水源这么少……"
→ "就说人民有智慧，有了。"
→ 分出一汪水，还有几根水藻。
→ 核心亮起耀眼光芒。"魔物，创造！"
→ 水团摇摆不定，不断扭曲。魔力凝聚，生成。收成一摊软泥，砸在泥土上。
→ [面板]
→ 水源怪伸出水藻想靠近核心，又羞怯不敢。
→ "阿水，精神点。第三层，交给你了。"
```

**关键差异**：机制说明（咒印效果、触发条件）不应在创造时解说，应放在**首次杀人时**通过画面揭示——读者看到喝水→倒下→石像补刀，自然理解"水有问题"。

## 修改流程

1. **读取样本**：每次修改新章节前，先通过浏览器在线查看样本对应章节（含多页），理解事件骨架。**样本只需要在线查看，不需要下载到本地项目。**
2. **读取卷纲**：涉及新魔物/新角色/新设定时，对照卷纲确认已有设计
3. **对比差异**：列出当前版本与样本的结构差异，确认修改方向。**样本仅作事件骨架参考，当前正文的原创内容（新增场景、多线交叉、设定展开）是作者的有意创作，不可当作"缺失"直接照搬样本填补**
4. **逐项修改**：用户逐条指出问题 → 逐条修正，不扩大修改范围
5. **数字一致性**：源质数值、魔物数量、时间跨度等数字前后对齐
6. **引用统一**：角色名、地名、道具名、技能名全文一致
7. **章尾检查**：每一章末尾必须有悬念钩子（动作切断/外部视角/新威胁逼近）
